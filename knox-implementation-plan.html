03Core types

Five enums and two structs replace the 23-field KnoxAction. If a field is not needed by a view, a filter or a renderer, it does not belong here.

pub enum Kind { Action, Decision, Doubt, Plan, Outcome }
pub enum State { Current, Superseded, Resolved, Open }
pub enum EdgeType { CausedBy, Supersedes, Resolves, Contradicts,
                      DependsOn, Implements, Verifies, Reverts, RelatesTo, Follows }
pub enum Source { Agent, Human, Ingest, Git }
pub enum PatternKind { Path, Symbol, Phrase }

pub struct Scope { // every read and write carries this
    pub project_id: ProjectId,
    pub session_id: Option<SessionId>,
    pub actor: String,
}

pub struct Entry {
    pub id: EntryId, pub kind: Kind, pub state: State,
    pub summary: String,   // ≤300 chars, enforced at write
    pub why: Option<String>, // ≤1000 chars
    pub confidence: f32, pub source: Source,
    pub refs: Vec<Ref>, pub seen: u32,
    pub created_at: i64,   // epoch ms — ordering is numeric
}

Two deliberate omissions. There is no is_current flag on the entry — state lives in entry_state and is derived from edges (D4). And there is no significance column: it defaulted to "major" on every write path, which made it a constant; importance is now expressed by the kind and by seen_count.

04Schema v6

Eleven tables, all additive. Every foreign key that matters is declared, every index matches a query the views actually run, and every CHECK closes a vocabulary.

CREATE TABLE project (id TEXT PRIMARY KEY, root TEXT NOT NULL UNIQUE,
  remote TEXT, name TEXT, created_at INTEGER NOT NULL);

CREATE TABLE session (id TEXT PRIMARY KEY,
  project_id TEXT NOT NULL REFERENCES project(id),
  actor TEXT NOT NULL, started_at INTEGER NOT NULL,
  last_seen INTEGER NOT NULL, ended_at INTEGER, parent_session TEXT);

CREATE TABLE entry (
  id TEXT PRIMARY KEY,              -- ULID, kind-prefixed: a_ d_ q_ p_ o_
  project_id TEXT NOT NULL REFERENCES project(id),
  session_id TEXT REFERENCES session(id),
  kind TEXT NOT NULL CHECK(kind IN ('action','decision','doubt','plan','outcome')),
  summary TEXT NOT NULL, why TEXT,
  confidence REAL NOT NULL DEFAULT 0.7,
  source TEXT NOT NULL CHECK(source IN ('agent','human','ingest','git')),
  provenance TEXT,                 -- json: transcript hash+offset, commit sha, rule id
  dedupe_key TEXT NOT NULL, seen_count INTEGER NOT NULL DEFAULT 1,
  created_at INTEGER NOT NULL);

CREATE INDEX entry_scope  ON entry(project_id, kind, created_at);
CREATE INDEX entry_dedupe ON entry(project_id, dedupe_key, created_at);

CREATE TABLE entry_ref (entry_id TEXT REFERENCES entry(id) ON DELETE CASCADE,
  type TEXT NOT NULL CHECK(type IN ('file','symbol','requirement','defect','tag')),
  value TEXT NOT NULL, role TEXT NOT NULL DEFAULT 'changed',
  PRIMARY KEY(entry_id, type, value));
CREATE INDEX ref_lookup ON entry_ref(type, value);

CREATE TABLE edge (src TEXT REFERENCES entry(id) ON DELETE CASCADE,
  dst TEXT REFERENCES entry(id) ON DELETE CASCADE,
  type TEXT NOT NULL, confidence REAL NOT NULL DEFAULT 1.0,
  created_at INTEGER NOT NULL, PRIMARY KEY(src, dst, type));

CREATE TABLE entry_state (entry_id TEXT PRIMARY KEY REFERENCES entry(id) ON DELETE CASCADE,
  state TEXT NOT NULL CHECK(state IN ('current','superseded','resolved','open')),
  by_entry TEXT);

CREATE TABLE rule (id TEXT PRIMARY KEY, entry_id TEXT NOT NULL REFERENCES entry(id),
  project_id TEXT NOT NULL, pattern_kind TEXT NOT NULL,
  pattern TEXT NOT NULL, severity TEXT NOT NULL,
  active INTEGER NOT NULL DEFAULT 1);

CREATE TABLE delta (hash TEXT PRIMARY KEY, entry_id TEXT NOT NULL,
  file TEXT NOT NULL, change TEXT NOT NULL, body BLOB);

CREATE TABLE ingest_log (source_hash TEXT NOT NULL, offset INTEGER NOT NULL,
  outcome TEXT NOT NULL, rule_id TEXT, reason TEXT, entry_id TEXT,
  PRIMARY KEY(source_hash, offset));

CREATE VIRTUAL TABLE entry_fts USING fts5(summary, why, content='entry');
CREATE TABLE schema_migrations (version INTEGER PRIMARY KEY,
  checksum TEXT NOT NULL, applied_at INTEGER NOT NULL);

Derived state, applied in the same transaction as the edge

fn apply_edge(tx: &Transaction, e: &Edge) -> Result<()> {
    match e.ty {
        EdgeType::Supersedes => set_state(tx, &e.dst, State::Superseded, Some(&e.src))?,
        EdgeType::Resolves   => set_state(tx, &e.dst, State::Resolved,   Some(&e.src))?,
        _ => {}
    }
    insert_edge(tx, e)
}

No triggers (D4). The state table is written by the same code path that writes the edge, so a test can call apply_edge directly and assert the state change without standing up a database transaction log.

Validation, inside the transaction

-- 1. every entry has a project that exists
SELECT count(*) FROM entry e LEFT JOIN project p ON p.id = e.project_id
 WHERE p.id IS NULL;                       -- must be 0

-- 2. no orphan edges
SELECT count(*) FROM edge g LEFT JOIN entry e ON e.id = g.src
 WHERE e.id IS NULL;                        -- must be 0

-- 3. state agrees with the supersession chain
SELECT count(*) FROM entry_state s
 WHERE s.state = 'superseded'
   AND NOT EXISTS (SELECT 1 FROM edge g
                    WHERE g.dst = s.entry_id AND g.type = 'supersedes');  -- must be 0

-- 4. FTS in sync
SELECT (count(*) FROM entry) - (count(*) FROM entry_fts);  -- must be 0

Plus a row-count diff per kind and a 20-row field-by-field sample. Any failed check rolls back and prints the failing query with its count — a migration that cannot say why it failed is not debuggable at 2am.

Non-negotiable

The backup is taken before the transaction opens, named knox.db.bak-v5-<timestamp>, and --restore is tested in CI against a deliberately corrupted migration. Silent partial migration of a memory product is unrecoverable.

Budget contract, testable as a property

For every read tool and every budget from 100 to 6000: tokens(response) ≤ budget. When items are dropped, omitted is non-zero and next is a valid cursor. When omitted is zero, next is null. A response that violates this fails CI.

07Retrieval

Hard filters, then a score, then clustering, then greedy packing. Four small functions, each with its own test file.

Score

ComponentWeightDefinition
ref match0.30exact file 1.0 · symbol 0.8 · same directory 0.4 · none 0
kind prior0.20decision 1.0 · open doubt 0.8 · action 0.5 · outcome 0.5 · plan 0.4
text0.15BM25 normalised within the result set; 0 when no query
recency0.10exp(-age/half_life): decision 180d · doubt 30d · action 14d · plan 14d
confidence0.10stored value
graph0.101.0 if one hop from a matched entry via depends_on / implements / caused_by
unresolved0.051.0 if an open doubt
fn rank(c: &[Candidate], f: &Focus) -> Vec<Scored> {
    let mut v: Vec<Scored> = c.iter().map(|e| Scored {
        score: 0.30*ref_match(e, f) + 0.20*kind_prior(e) + 0.15*text(e, f)
             + 0.10*recency(e)    + 0.10*e.confidence + 0.10*graph(e, f)
             + 0.05*unresolved(e),
        id: e.id.clone(),
    }).collect();
    // stable ties: score desc, then id asc — byte-identical output across runs
    v.sort_by(|a, b| b.score.partial_cmp(&a.score).unwrap_or(Equal)
                       .then_with(|| a.id.cmp(&b.id)));
    v
}

Pack

fn pack(ranked: Vec<Scored>, budget: u32, view: View) -> Packed {
    let mut used = header_cost(view);        // ~20 tokens
    let mut out = Vec::new(); let mut omitted = 0;
    // one constraint is reserved before anything else — the only non-greedy rule
    if let Some(c) = ranked.iter().find(|s| is_constraint(s)) {
        used += tokens(render(c)); out.push(c.clone());
    }
    for s in ranked {
        if out.contains(&s) { continue }
        let cost = tokens(render(&s));
        if used + cost <= budget { used += cost; out.push(s) }
        else { omitted += 1 }
    }
    Packed { items: out, used, omitted, next: cursor(view, &ranked, omitted) }
}

The reserved constraint is the one deliberate exception to pure greedy packing: an agent that gets twelve recent actions and no constraints has been given the least useful part of the answer. rank_constraint_reserved is a named test for exactly this.

08Guardrails

A rule is a row, not a sentence. That is what makes the check explainable, testable, and cheap enough to run before every edit.

CREATE TABLE rule (id TEXT PRIMARY KEY, entry_id TEXT NOT NULL,
  project_id TEXT NOT NULL,
  pattern_kind TEXT CHECK(pattern_kind IN ('path','symbol','phrase')),
  pattern TEXT NOT NULL, severity TEXT CHECK(severity IN ('strict','advisory')),
  active INTEGER DEFAULT 1);

-- a decision that prohibits something creates its rule rows in the same transaction
-- pattern_kind=path  -> glob against touched files
-- pattern_kind=symbol-> exact symbol match
-- pattern_kind=phrase-> word-boundary match against intent, ≥2 distinct tokens

Strict blocks only on a strict-severity rule at confidence ≥ 0.8, which is the same threshold the previous matcher had — but the evidence that produces the number is now a table row, so guard_conf_levels can assert each band instead of hoping.

What replaces the old matcher

The current implementation tokenises and applies a coverage threshold with negation handling. That was a real improvement over substring matching, but it still compares prose to prose. The rule table makes the comparison structural: a path rule matches a path, a symbol rule matches a symbol, and only phrase rules need text similarity — which is why the ladder can be honest about the 0.30 FTS band.

What I could not verify

There is no Rust toolchain in my environment. Nothing in this plan has been compiled, no migration has been run, and the 3,412-token figure comes from serialising the schemas in source rather than from a live tools/list. The design is grounded in 16,555 lines read and three measured surfaces; the code samples are contracts to implement, not code that already builds. Phase 0 exists to replace that gap with numbers.

Ship the budget before the migration, measure the empty-result rate before tuning a single weight, and never let a read return a confident empty answer.
